How the system works (one paragraph for your own memory)

  • Collector (code/collect.py, .github/workflows/collect.yml): a GitHub Actions workflow calls the TfL Unified API about every 15 minutes (triggered by an external cron service via workflow_dispatch because GitHub's own schedule is unreliable) and appends raw CSVs for crowding, line supply, line status, station disruptions, lifts and station supply to the data branch, with a collection_log.csv of what each run got. tfl-status.html shows the latest runs.
  • Build (code/build.py, .github/workflows/build.yml): once a day (00:40 UTC) and by hand, recomputes every processed JSON file in processed/ on the data branch from all the raw files, so numbers always match the data. It also fetches TfL's route sequences (code/fetch_routes.py) to name train directions.
  • Site (index.html, project.html, portfolio.html, assets/): static pages on GitHub Pages; the JavaScript (assets/js/charts.js, Vega-Lite and D3) reads the processed files from raw.githubusercontent.com/.../data/processed/ and draws every chart in the browser, so charts update without anyone touching them.

Decision log

  • Demand is not observed. Crowding at stations is the outcome of demand and supply (and of TfL's own controls); supply is observed only through trains with a live prediction.
  • Self-scaled 0 to 100 (busiest quarter-hour or hour of the typical week) for all week-pattern plots, instead of TfL's fixed 2019 reference, because the questions are about patterns within a week.
  • Median across days for every typical value; complete days only (56 of 64 daytime quarter-hours); mean across stations within a slot.
  • Masking of closed, exit-only and fully suspended stations because TfL's count is capped when entry is restricted.
  • Waterloo & City left out of every line list and chart (two stations).
  • 15-minute grid on the London clock; the earlier of two runs in one slot is used.
  • Planned works are counted as lost supply in Plot 6 and excluded from Appendix B.
  • Colours: orange crowding, plum supply, blue weekend or quiet, grey usual or no data; line colours are TfL's.
  • Thresholds that are judgement, not estimated: station types 1.8 / 0.9 / 1.1 (Plot 2); 20% fewer trains, deviation above 2, 12 hours a week (Plot 6); top and bottom 10% (Appendix A); 5 and 10 days for dots and bands (Plot 5); 5 events for a band (Appendix B).

Where the marking criteria are evidenced (facts only)

  • Open-data approach: public repository; raw CSVs and processed JSON on the data branch; code in code/; data dictionary in data/README.md.
  • Data design: each plot has a stated question and the variables that answer it (notes above).

  • Visual impact and grammar of graphics: Vega-Lite specifications (encodings of position, colour, size), interactive controls on every plot, consistent colour grammar.
